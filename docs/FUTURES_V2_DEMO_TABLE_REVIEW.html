What We Should Not Duplicate

Temptation Use Instead Reason
A separate Futures college table college + college_external_id AFDB already has colleges; source IDs belong in mapping rows.
Treating JoSAA as an exam counselling_process JoSAA is allotment/counseling. JEE Main and JEE Advanced are the exams.
Using college.entrance_test for new logic college_exam The existing field is legacy/unclear and hard to query correctly.
CSV-only IDs becoming canonical AFDB IDs plus source keys in mapping tables Generated demo IDs are fine for fixtures, not long-term joins.
A new cutoff table Extended cutoffs The AFDB table already exists for this fact; extend it with JoSAA dimensions.
